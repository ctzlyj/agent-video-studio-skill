# ai-drama：AI 漫剧 / AI 真人短剧 / 单镜生成

视频镜头由灵境 CLI 调用视频模型生成（默认 Seedance 2.5）；人物、场景、分镜图由 `scripts/imagegen.py` 按配置的模型链生成。
吸收的方法：lingjing-director（故事版、生成段、视觉质检）、djyy1031/ai-comic-drama-director-skills（资产规划、连续性审核）、
suihe1/short-drama-production 与 xixihhhh/ai-short-drama-skill（剧本→分镜→视频→声音→粗剪→QC）、awesome-short-drama-skills（提示词写法合集）。

**灵境的操作契约由 `lingjing` skill 负责**（认证、画布写入、扣费两阶段、任务恢复、成片交付）。执行灵境命令前读它的 `SKILL.md` 与 `cli.md`；两者冲突时以它为准。本文件只决定怎么创作，以及与它默认值不同的地方：
- 图片一律用 `scripts/imagegen.py` 生成后 `lingjing asset upload` 上传，作为 `image-source` 节点；**不调用灵境的图片生成**。
- 视频默认 `Seedance 2.5`。用户点名其它模型（可灵、万相、Veo、海螺、Vidu、MiniMax H3…）时先 `lingjing model list -t <场景>` 确认可用。

## 第一次用之前（一次性，约 2 分钟）

Mac 实测里，用户走到第一次花钱提交才被拦：`错误: [539] 使用素材库功能，请先同意Seedance2.0模型使用承诺书`。这些都是**要用户本人做**的事，先做完再开始创作：
1. **登录灵境**：`lingjing login`。无头 / 沙箱里的 agent 打不开浏览器时，用 `lingjing login --no-open`，它会打印一条 `https://oauth2.jdcloud.com/authorize?...` 授权链接；**把这条链接发给用户**，让用户在自己的浏览器里完成登录，agent 在本机等回调。第一次可能报 `网络请求失败`，再跑一次通常就给出链接。
2. **签《Seedance2.0 模型使用承诺书》**：只能用户本人在灵境网页「素材库」里读完并签署（`lingjing` 会给出链接，`userActionRequired: read_and_sign_in_browser`）。不签，视频参考图送审和付费提交都会被拦（错误码 539）。
3. **看余额**：`lingjing wallet`。`canSpend: true` 只表示提交闸不会拦，**不代表余额够跑完**，预算看报价。
4. **自检**：`python scripts/check_env.py`。

## 流程
1. **剧本**：一集 30–90 秒。写成分场剧本：场景、时间、人物、动作、对白、情绪。对白短，一句一个情绪点。确认后再出图。
2. **配乐方案（与剧本/分镜一起确认）**：根据题材给 2 个候选，用 `score.py` 各出 20–30 秒试听，让用户听完再定。不要等成片才发现音乐不合适。
   - 轻松职场/教学漫剧 → `workplace`（默认）/ `healing` / `warm`
   - 治愈日常、真人情感 → `healing`（真人短剧默认）/ `warm`
   - 搞笑喜剧 → `comedy`；热血/成长/比赛 → `hotblood`
   - 悬疑惊悚 → `suspense`；史诗/历史 → `cinematic`；科幻/科技 → `tech`
   - 古风/国风、复杂管弦：合成器只做近似；要求高时改用用户授权音乐 `music.file` 或授权的 AI 作曲（付费前先报价确认）
   - 试听命令：`python "$SKILL/scripts/score.py" --style workplace --seconds 25 -o audition_workplace.wav --mood calm,build,climax,resolve`
   - 写进 `project.json`：`"music": {"style": "workplace"}`；每镜标 `mood`，片尾用 `resolve` 让音乐收束。**AI 剧不要用内置 BGM**；只有用户明确要求才写 `"track": "default", "allowBuiltinTrack": true`。
3. **资产卡**（写进 `characters.md`）：每个角色一张设定——外貌固定描述（发型、服装、配色、体型、标志物；服装上要有指定文字时写清字样和位置，质检时检查是否变形）、性格、声音。每个场景一张——空间、光线、时间、色调。
   - 漫剧：先定画风一句话（如"日系赛璐璐、干净线稿、平涂阴影"），所有提示词都以它开头。
   - 每个角色出正面全身设定图 + 三视图；每个场景出 1 张空镜。设定图用户确认后锁定，后续所有镜头都以它们为参考，不再改外貌描述。
4. **故事版**：按场景分页，每页 6–8 镜，每镜写镜号、时长、景别/机位/运镜、画面、表演、对白、声音。单节拍镜头 2–4 秒。
5. **生成段规划**：一次生成尽量长（Seedance 2.5 最长 15 秒；**这一段的旁白不要超过约 50 个汉字**，见下方「旁白字数」），覆盖同一场景内相邻镜号；换场景/时间或超时长才另起一段。prompt 按镜号顺序写出段内每镜的画面、时长、运镜、出入点，用 `{{Ref N}}` 引用参考图。
6. **报价 → 确认 → 提交**：⚠️ 报价接口与实扣差距很大。**2026-11-10 本次实测：设置了 mode=720p，成片实际是 1920×1080；13 秒一段实扣 48.8 元，10 秒一段 37.6 元，约为报价的 3.5 倍；预估 450 元，实际约 856 元。** 因此：
   - 默认按“报价 X 元，按实测约 3.5X 元准备预算”告知用户；不要只报 1.67 倍。
   - 提交前确认实际输出分辨率和计费口径；`mode=720p` 在 reference-video 下不一定生效，不能凭参数名判断成片清晰度。
   - 报价给用户时写清段数、每段时长、总价和 3.5 倍上限；用户授权以较高金额为准后才 `node run -y`。
   - 先用 480p/短样片试一段（若平台确实支持）再批量；交付后用 `lingjing usage show <taskId>` 核对实扣并如实报告。
7. **质检**：每段抽帧看人物是否一致、有无变形/多手指/穿帮、口型和动作是否合理、是否出现文字水印；**逐镜检查有没有多出未列出的角色、或漏掉剧本要求的角色**。不合格只重跑该段（同节点 `--attempt 2`），重跑前再报价。
8. **声音与合成**：配音（每角色固定音色）、配乐（第 2 步选定的 `music.style`，按剧情给每镜标 `mood`）、音效；字幕。生成视频自带的对白/环境音用 `clipAudio` 登记，`audio.py` 会把它和旁白一起送进闪避侧链，AI 剧默认把音乐床压到 0.50、闪避 8:1。片段拼接用 `lingjing clip concat` 写回画布 `video-clip`，或把片段作为 `videos` 素材放进本 skill 的 HTML 工程，加片头、字幕、署名后统一 `build.py --final`。
9. **交付**：成片、每段任务 ID 与费用合计（报价/实扣）、未通过质检被替换的段、灵境画布链接、**配乐预设与试听文件**、没有验到的点。

## 角色限制（写进每一段 prompt）

未写限制时，模型容易新增“看起来合理”的路人/同事。每段 prompt 固定加一行：

```text
本段只出现：A（描述）、B（描述）。不得出现其他角色、路人、群众、动物或多余人物；不要新增未列出的角色。
```

质检时逐帧核对“多余角色 / 缺角色”；发现多余角色只重跑该段，不要用后期裁切掩盖。

## 画面文字（屏幕、牌子、包装）

AI 视频里的文字几乎都会乱码或变形。prompt 明确写：

```text
画面中的屏幕、手机、牌子、海报、包装、PPT 只画图标、色块或抽象线条，不写任何文字、数字、logo；需要出现的文字由后期 HTML 叠加。
```

需要真实文字时，用本 skill 的 HTML 工程叠字（字体、字号、位置可控），不要把文字交给视频模型。

## 旁白字数与镜头时长

先写旁白，再定每段 `duration`；不要先定 15 秒再硬塞旁白。

| 视频段时长 | 建议旁白字数（中文，不含标点） | 说明 |
|---|---|---|
| 8 秒 | 26–30 字 | 开头留约 0.5 秒 |
| 10 秒 | 33–38 字 | 3.9 字/秒估算 |
| 13 秒 | 45–50 字 | 本次实测可用区间 |
| 15 秒 | ≤ 50 字 | 再多会超出画面，需删字/拆段/降速 |

旁白超出画面时：删字最直接；或拆到相邻段；或降低 `speed`。不要靠“让画面空转”等旁白说完。

## 读音校对

中文多音字在业务/教学稿里很常见。配音后跑：

```bash
python scripts/voice.py <项目> --check
python scripts/voice.py <项目> --check --asr
```

把有问题的词写进 `project.json.voice.pronounce`（例如 `{"还款": "环款", "长度": "常度"}`），字幕仍用原文。实测替换表、ASR 方法和局限见 `references/voice.md`；交付前列出“请重点听”的词给用户。

## 质检清单

- 人物：脸、发型、服装、配色、标志物是否与设定图一致；有没有多余角色/缺角色。
- 画面：手指、肢体、道具数量、透视、穿帮、闪烁、变形。
- 文字：屏幕/牌子/包装是否出现乱码、错字、水印；需要的文字是否已用 HTML 叠加。
- 动作与口型：对白段口型是否大致对上；动作是否自然；有没有突然静止。
- 节奏：旁白是否在段内说完；有没有长时间空转；镜头切换是否跟旁白重音对齐。
- 规格：实际分辨率、画幅、帧率、时长；与报价时的假设是否一致。
- 声音：对白/环境音是否被音乐盖住；片尾是否收束；响度与真峰值是否达标。

## 重新终检同一项目

`finalize.py` 默认拒绝覆盖 `deliver/` 里的旧文件，这是保护。报错时按提示三选一：

1. 保留旧交付、做新版本：`python scripts/new_project.py "<项目目录>" --version`，把改动同步到新目录后再终检。
2. 把旧 `deliver/` 整个移到 `deliver_<时间戳>/`，再对同一项目重跑 `finalize.py`。
3. 确认某个旧文件确实不要了，只删那一个文件再重跑。

不要为了绕过保护去改脚本里的覆盖检查。

## 真人短剧的审核限制
Seedance 合规素材库会拦截"看起来像真实人物"的参考图，纯 AI 生成的写实人物也可能被拦。真人短剧先拿一张角色图走一次送审（不扣费）；被拒时：改为不带人脸参考的文生视频、换成插画/半写实画风、或换用户点名的其它模型。不要尝试绕过审核。首次使用要先在灵境网页签《Seedance2.0 模型使用承诺书》。

## 单镜生成（hybrid）
代码动画里只需要几段实拍感镜头时：为每段写一句画面描述 + 首帧图（`imagegen.py`），报价确认后用 `image-to-video` 生成 5–10 秒，下载放进 `assets/`，在 `project.json.videos` 登记后按普通视频素材使用。
