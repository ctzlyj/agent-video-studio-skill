# ai-drama：AI 漫剧 / AI 真人短剧 / 单镜生成

视频镜头由灵境 CLI 调用视频模型生成（默认 Seedance 2.5）；人物、场景、分镜图由 `scripts/imagegen.py` 按配置的模型链生成。
吸收的方法：lingjing-director（故事版、生成段、视觉质检）、djyy1031/ai-comic-drama-director-skills（资产规划、连续性审核）、
suihe1/short-drama-production 与 xixihhhh/ai-short-drama-skill（剧本→分镜→视频→声音→粗剪→QC）、awesome-short-drama-skills（提示词写法合集）。

**灵境的操作契约由 `lingjing` skill 负责**（认证、画布写入、扣费两阶段、任务恢复、成片交付）。执行灵境命令前读它的 `SKILL.md` 与 `cli.md`；两者冲突时以它为准。本文件只决定怎么创作，以及与它默认值不同的地方：
- 图片一律用 `scripts/imagegen.py` 生成后 `lingjing asset upload` 上传，作为 `image-source` 节点；**不调用灵境的图片生成**。
- 视频默认 `Seedance 2.5`。用户点名其它模型（可灵、万相、Veo、海螺、Vidu、MiniMax H3…）时先 `lingjing model list -t <场景>` 确认可用。

## 第一次用之前（一次性，约 2 分钟）

Mac 实测里，用户走到第一次花钱提交才被拦：`错误: [539] 使用素材库功能，请先同意Seedance2.0模型使用承诺书`。这些都是**要用户本人做**的事，先做完再开始创作：
1. **登录灵境**：`lingjing login`。无头 / 沙箱里的 agent 打不开浏览器时，用 `lingjing login --no-open`，它会打印一条 `https://oauth2.jdcloud.com/authorize?...` 授权链接；**把这条链接发给用户**，让用户在自己的浏览器里完成登录，agent 在本机等回调。第一次可能报 `网络请求失败`，再跑一次通常就给出链接。
2. **签《Seedance2.0 模型使用承诺书》**：只能用户本人在灵境网页「素材库」里读完并签署（`lingjing` 会给出链接，`userActionRequired: read_and_sign_in_browser`）。不签，视频参考图送审和付费提交都会被拦（错误码 539）。
3. **看余额**：`lingjing wallet`。`canSpend: true` 只表示提交闸不会拦，**不代表余额够跑完**，预算看报价。
4. **自检**：`python scripts/check_env.py`。

## 流程
1. **剧本**：一集 30–90 秒。写成分场剧本：场景、时间、人物、动作、对白、情绪。对白短，一句一个情绪点。确认后再出图。
2. **配乐方案与试听（与剧本/分镜一起确认）**：按题材从 `references/music.md` 的提示词模板库选 **2 个不同风格**的候选，用灵境 **MiniMax Music 2.6** 生成纯音乐；生成后先用 `scripts/music_screen.py` 做客观粗筛，再把通过的 1–2 个文件路径给用户试听，用户选定前不要出片。
   - `lingjing model quote -t audio-synthesis "MiniMax Music 2.6"` 返回 `quote:null`（系统不报价）；本次实测每首约 **0.45 元**、约 1 分 50 秒。提交前告诉用户“2 首预计约 0.9 元，系统不报价，以实际账单为准”，确认后才 `-y`。
   - 生成命令示例：`lingjing model exec -t audio-synthesis "MiniMax Music 2.6" --set prompt="<提示词>" --set lyrics="[Intro]\n[Instrumental]" -y`；`lyrics` 表示纯音乐，不要写歌词。
   - 下载 mp3 到 `assets/music/`；粗筛示例：`python scripts/music_screen.py assets/music/workplace-1.mp3 --expect-mode major --bpm-min 100 --bpm-max 135 --centroid-min 1200`。小调、偏暗、BPM 不符的候选先淘汰，不要拿一堆错误方向让用户挑。
   - 用户选定后写 `"music": {"file": "assets/music/xxx.mp3", "volume": 0.10}`。AI 剧**不要用内置 BGM**；只有用户明确要求才写 `"track":"default","allowBuiltinTrack":true`。
   - 代码合成配乐（`music.style`）只做氛围衬底，没有真正旋律线；AI 剧主配乐不要用它。
3. **资产卡**（写进 `characters.md`）：每个角色一张设定——外貌固定描述（发型、服装、配色、体型、标志物；服装上要有指定文字时写清字样和位置，质检时检查是否变形）、性格、声音。每个场景一张——空间、光线、时间、色调。
   - 漫剧：先定画风一句话（如"日系赛璐璐、干净线稿、平涂阴影"），所有提示词都以它开头。
   - 每个角色出正面全身设定图 + 三视图；每个场景出 1 张空镜。设定图用户确认后锁定，后续所有镜头都以它们为参考，不再改外貌描述。
4. **故事版**：按场景分页，每页 6–8 镜，每镜写镜号、时长、景别/机位/运镜、画面、表演、对白、声音。单节拍镜头 2–4 秒。
5. **生成段规划**：一次生成尽量长（Seedance 2.5 最长 15 秒；**15 秒段旁白约 70–78 字（女声 +12%）；具体见下方「旁白字数」**），覆盖同一场景内相邻镜号；换场景/时间或超时长才另起一段。prompt 按镜号顺序写出段内每镜的画面、时长、运镜、出入点，用 `{{Ref N}}` 引用参考图。
6. **报价 → 确认 → 提交**：⚠️ 报价接口与实扣差距很大。**2026-11-10 本次实测：设置了 mode=720p，成片实际是 1920×1080；13 秒一段实扣 48.8 元，10 秒一段 37.6 元，约为报价的 3.5 倍；本次 21 个生成任务实扣合计约 856 元，预估 450 元。** 因此：
   - 默认按“报价 X 元，按实测约 3.5X 元准备预算”告知用户；不要只报 1.67 倍。
   - 提交前确认实际输出分辨率和计费口径；`mode=720p` 在 reference-video 下不一定生效（本次未独立核实平台口径），不能凭参数名判断成片清晰度；按实际输出分辨率和账单计费。
   - 报价给用户时写清段数、每段时长、总价和 3.5 倍上限；用户授权以较高金额为准后才 `node run -y`。
   - 先用 480p/短样片试一段（若平台确实支持）再批量；交付后用 `lingjing usage show <taskId>` 核对实扣并如实报告。
7. **质检**：每段抽帧看人物是否一致、有无变形/多手指/穿帮、口型和动作是否合理、是否出现文字水印；**逐镜检查有没有多出未列出的角色、或漏掉剧本要求的角色**。不合格只重跑该段（同节点 `--attempt 2`），重跑前再报价。
8. **声音与合成**：配音（每角色固定音色）、配乐（第 2 步选定的 `music.file`，默认 volume 0.10；按剧情给每镜标 `mood`）、音效；字幕。生成视频自带的对白/环境音用 `clipAudio` 登记，`audio.py` 会把它和旁白一起送进闪避侧链，AI 剧 `music.file` 默认 0.10，旁白/clipAudio 一起进闪避侧链，闪避 8:1。片段拼接用 `lingjing clip concat` 写回画布 `video-clip`，或把片段作为 `videos` 素材放进本 skill 的 HTML 工程，加片头、字幕、署名后统一 `build.py --final`。
9. **交付**：成片、每段任务 ID 与费用合计（报价/实扣）、未通过质检被替换的段、灵境画布链接、**配乐文件、粗筛结果与用户试听确认**、没有验到的点（至少写：读音只能用户听；配乐好不好听只能用户听；真实平台的 mode/分辨率/实扣以账单为准）。

## 角色限制（写进每一段 prompt）

未写限制时，模型容易新增“看起来合理”的路人/同事。每段 prompt 固定加一行：

```text
本段只出现：A（描述）、B（描述）。不得出现其他角色、路人、群众、动物或多余人物；不要新增未列出的角色。
```

质检时逐帧核对“多余角色 / 缺角色”；发现多余角色只重跑该段，不要用后期裁切掩盖。

## 画面文字（屏幕、牌子、包装）

AI 视频里的文字几乎都会乱码或变形。prompt 明确写：

```text
画面中的屏幕、手机、牌子、海报、包装、PPT 只画图标、色块或抽象线条，不写任何文字、数字、logo；需要出现的文字由后期 HTML 叠加。
```

需要真实文字时，用本 skill 的 HTML 工程叠字（字体、字号、位置可控），不要把文字交给视频模型。

## 参考图顺序与品牌/制服

一次性用多张参考图时，`{{Ref N}}` 的序号必须和连线顺序一致。推荐顺序：**角色 A 主图 → 角色 B 主图 → 场景空镜 → 品牌/制服参考图**；在 prompt 里逐个对应：

```text
{{Ref 1}} 是角色 A，{{Ref 2}} 是角色 B，{{Ref 3}} 是场景，{{Ref 4}} 只用于马甲样式。
本段只出现 A、B，不得出现其他角色、路人或群众。
马甲样式只参考参考图，其他衣着不要参考参考图；角色原有发型、裤子、鞋子和配饰保持不变。
```

制服/品牌参考图只控制它该控制的部件（例如马甲的颜色、口袋、字样位置）；不要让模型把参考图里的模特、背景、姿势、下装一并套用。需要出现品牌字样时，仍由 HTML 后期叠加，AI 只画色块和图标。

## 配音声线与语速

- **教学/培训默认 `zh-CN-XiaoxiaoNeural` +12%**：温暖、清楚，适合讲解；`new_project.py` 的 AI 剧项目已按这个默认写入。
- `zh-CN-XiaoyiNeural`：更活泼、年轻，适合搞笑/轻松短剧；可配 `+10%`。
- `zh-CN-YunxiNeural` / `zh-CN-YunyangNeural`：男声，分别偏温和/新闻播报；需要男声时再选。
- 用户说“语速很慢”时，教学类先把 `voice.rate` 提到 `+10%~+12%`，不要靠 `speed` 硬压画面；`voice.py` 的 edge 引擎已增加到 5 次重试（指数退避），仍失败再换离线 SAPI/`say` 或自带录音。
- 音色/语速改完先跑 `voice.py --check`，再跑 `voice.py`；改文案后才需要重配，文本不变有缓存。

## 旁白字数与镜头时长

先写旁白，再定每段 `duration`；不要先定 10 秒再硬塞字。女声 `+10%~+12%` 时实测约 **5.0–5.6 字/秒**（含少量停顿）：

| 视频段时长 | 建议旁白字数（中文，不含标点） | 说明 |
|---|---|---|
| 8 秒 | 40–45 字 | 开头留约 0.5 秒 |
| 10 秒 | 45–52 字 | 教学/培训主力时长 |
| 13 秒 | 60–68 字 | 本次实测可用区间 |
| 15 秒 | 70–78 字 | 接近 5.0–5.6 字/秒，留一点停顿 |

如果仍用 `+0%` 的老语速（约 3.9 字/秒），10 秒约 33–38 字、13 秒约 45–50 字。**不要套错表。** `timeline.py` 现在会输出每镜 `charsPerSec`，并在旁白比 `dur` 长时打印 `WARN ... tail will be cut`；看到警告就加 `dur`、删字或拆段。

## 本集小结、片尾与补画面

教学/培训类每集结尾加一个 `summary` 页，列 3–4 条本集要点；片尾用 `endcard`，署名/出品方由 HTML 叠加，不让 AI 生成。模板 `assets/template/scenes.js` 已内置：

- `summary`：渐变角度呼吸、进度条正弦推进、要点错峰入场；
- `endcard`：渐变漂移、标题轻微浮动、呼吸光；
- 两者都有持续微动效，避免 `qa.py` 的 **6 秒**冻结阈值误报。长停留页不要做成完全静态。

`project.json` 示例：

```json
{"id": "s90", "type": "summary", "mood": "resolve", "dur": 8,
 "data": {"heading": "本集小结", "items": ["要点一", "要点二", "要点三"]}}
```

生成视频片段比旁白短时，用模板的 `clip` 场景正放→倒放补画面，不要停在最后一帧：

```json
{"id": "s03", "type": "clip", "mood": "build", "dur": 12,
 "data": {"video": "clip1", "clipDur": 8.0, "x": 0, "y": 0, "w": 1920, "h": 1080}}
```

`clipDur` 填生成视频的实际秒数；模板按 `pingPong` 播放：0→8 秒正放，8→16 秒倒放，循环到镜头结束。

## 读音校对

中文多音字在业务/教学稿里很常见。配音后跑：

```bash
python scripts/voice.py <项目> --check
python scripts/voice.py <项目> --check --asr
```

把有问题的词写进 `project.json.voice.pronounce`（例如 `{"还款": "环款", "长度": "常度"}`），字幕仍用原文。实测替换表、ASR 方法和局限见 `references/voice.md`；交付前列出“请重点听”的词给用户。

## 质检清单

- 人物：脸、发型、服装、配色、标志物是否与设定图一致；有没有多余角色/缺角色。
- 画面：手指、肢体、道具数量、透视、穿帮、闪烁、变形。
- 文字：屏幕/牌子/包装是否出现乱码、错字、水印；需要的文字是否已用 HTML 叠加。
- 动作与口型：对白段口型是否大致对上；动作是否自然；有没有突然静止。
- 节奏：旁白是否在段内说完；有没有长时间空转；镜头切换是否跟旁白重音对齐。
- 规格：实际分辨率、画幅、帧率、时长；与报价时的假设是否一致。
- 声音：对白/环境音是否被音乐盖住；片尾是否收束；响度与真峰值是否达标。

## 重新终检同一项目

`finalize.py` 默认拒绝覆盖 `deliver/` 里的旧文件，这是保护。报错时按提示三选一：

1. 保留旧交付、做新版本：`python scripts/new_project.py "<项目目录>" --version`，把改动同步到新目录后再终检。
2. 把旧 `deliver/` 整个移到 `deliver_<时间戳>/`，再对同一项目重跑 `finalize.py`。
3. 确认某个旧文件确实不要了，只删那一个文件再重跑。

不要为了绕过保护去改脚本里的覆盖检查。

## 只重做音频，不重做视频素材

已经生成好的 `mp4` 片段不要重新提交 Seedance。只改旁白/配乐/语速时，按下面的顺序重跑本 skill 的合成层：

```bash
python scripts/voice.py <项目>            # 只有旁白改了才需要
python scripts/timeline.py <项目>
python scripts/audio.py <项目>
python scripts/render.py <项目> --final   # 重新渲染 HTML 合成层，不重新生成 AI 视频
python scripts/finalize.py <项目>
```

- 只改配乐：跳过 `voice.py`，直接 timeline → audio → render → finalize。
- 只改旁白/语速：先 `voice.py --check`，再 voice → timeline → audio → render → finalize。
- 先看小样：`render.py --sheet` 或 `build.py --preview`，确认后再跑 `--final`；本次四集并行渲染约 25 分钟，具体随机器和画面复杂度变化。
- 生成视频片段仍放在原 `assets/` / `videos` 里；不要因为只改音频就重新生成或覆盖它们。

## 真人短剧的审核限制
Seedance 合规素材库会拦截"看起来像真实人物"的参考图，纯 AI 生成的写实人物也可能被拦。真人短剧先拿一张角色图走一次送审（不扣费）；被拒时：改为不带人脸参考的文生视频、换成插画/半写实画风、或换用户点名的其它模型。不要尝试绕过审核。首次使用要先在灵境网页签《Seedance2.0 模型使用承诺书》。

## 单镜生成（hybrid）
代码动画里只需要几段实拍感镜头时：为每段写一句画面描述 + 首帧图（`imagegen.py`），报价确认后用 `image-to-video` 生成 5–10 秒，下载放进 `assets/`，在 `project.json.videos` 登记后按普通视频素材使用。
