# 炫技工具箱：着色器后期 + 画面事件钉在旁白词上

做"让人惊艳"的片子（抖音、发布会开场、品牌片）时用。普通汇报片不需要，用默认的 DOM 画法即可。

## 1. 两层结构：Canvas 画内容，着色器统一加质感

模板默认每镜是 DOM 元素。要更强的质感时改用下面的结构（拷贝 `assets/fx/` 到项目根，在 `index.html` 里按 `avs-runtime.js` → `fx.js` → `lib.js` → `scenes.js` 的顺序引入）：

- `lib.js`：一块共享的 2D 画布 `L.C`。提供 `plate`（摄影图 + 推拉摇移）、`glow`、`text`（带辉光/描边/抖动）、`line`、`rect`、`dim`、`particles`（固定种子的粒子，纯时间函数）。
- `fx.js`：一道全屏 WebGL2 着色器，把 `L.C` 当纹理，统一加**色差、多采样辉光、横向拖尾（变形镜头光斑）、光扫转场、故障切片、屏幕震动、暗角、胶片颗粒、冷→暖调色**。参数由 `FX.apply(L.C, t, {warm, ca, bloom, sweep, glitch, shake, vig, flash, sat, streak})` 每帧传入。
- 每镜只做两件事：往 `L.C` 上画；写 `FXS.*` 参数。最后一次性 `FX.apply`。冲击（砍价、盖章、压下）= 同一时刻给 `shake / flash / ca / glitch` 一个指数衰减包络。
- 速度：无头 Chromium 用软件渲染（SwiftShader），1080×1920 约 0.1–0.4 秒/帧；90 秒、30fps 的片子终版约 15–25 分钟。**先用 `--preview`（540×960、12fps）看节奏。**

## 2. 把画面事件钉在旁白说出关键词的瞬间

不要凭感觉写"第 3.4 秒数字落下"。做法：

1. `voice.py` 生成每镜旁白后，`python scripts/transcribe.py <audio/vo/sXX.wav> --words` 得到每个字的开始时间。
2. 在 `scenes.js` 顶部建一张 `CUE` 表：`sXX: { 事件名: 镜内 lead + 词开始时间 }`。
3. 画面里的所有事件（数字落定、盖章、划线、点亮）都用 `CUE.sXX.事件名` 作起点。
4. 改旁白后重新转写、改 `CUE`，画面自动跟着。出片前用词级时间戳对一遍：偏差 > 0.45 秒的要修。

## 3. 每镜独立音色（冷 / 暖对比）

`project.json` 的镜头可写 `"voiceCfg": {"rate": "-6%", "pitch": "-6Hz"}` 覆盖全局音色参数。常用：问题段用"冷"（慢、低），转折后用"暖"（正常、略高），高潮段用"热"（快、略高）。只在需要叙事对比时用，不要每镜都换。

## 4. 竖屏短视频的节奏检查

- 每 1.5–2.5 秒必须有一次画面事件。用运动量分析（相邻帧平均差）找出静止窗口；**每帧都不能完全静止**：加慢速推拉、呼吸光、漂浮粒子。
- 第一帧就是封面，必须有完整内容；前 2 秒要有"停手"的东西（反常识问句 + 强动作）。
- 重要内容放在底部 190 像素以上、右侧 120 像素以内（平台按钮会盖住）。
- 数字：滚动 + 辉光 + 落定那一帧给 `flash/shake`，比静态字强得多。

## 5. 已知限制

- 着色器在软件渲染下较慢；不要在着色器里加每像素大循环（本模板的辉光是 12 采样，拖尾是 17 采样，已是上限）。
- 3D（Three.js）在软件渲染下慢一个量级，除非有独显，否则用 2D + 后期。
- 生成式摄影图里偶有多余的字或手指问题：文字一律由代码排，**不使用图里的任何文字**，出图后要看一遍。

## 6. 不要做成"带特效的 PPT"（2026-11 一次返工的教训）

- **不要整屏铺摄影图当每镜背景。** 每镜换一张底图 + 叠字 + 光效，看起来就是 PPT。底图只能做"证据"：生图 → `rembg` 抠成透明底 → 作为实物浮在动画里。
- **一镜到底**：一个世界 + 一条相机路径（单调三次样条，无过冲），场景只是时间段。相机的位置、缩放、速度驱动运动模糊；镜头间用"相机穿过去"代替淡入淡出。
- **主体必须是看得懂、有因果的具体物体**（价格牌被砍、柱子被压平、灯被点亮、卡车开过、缆绳被压断 vs 一张网托住），**不要用抽象光点矩阵当主体**（一万个点 = 屏保，观众看不出意义）。数字可以靠 HUD 叠层，但要从一个世界里的事件"长出来"。
- **文字画在着色器之后的清晰叠层画布上**（`L.useCtx(overlayCtx)`），不要让文字过辉光、色差和运动模糊。
- 对比演示（一根线 vs 一张网）用屏幕空间的舞台、压暗背景、关掉拖尾和运动模糊，线条才读得清。

## 7. 软件渲染的性能预算（实测）

无头 Chromium 的 WebGL 走 CPU（SwiftShader），着色器采样数就是渲染时间：
- 每帧 JS 绘制约 30–60 ms，主要成本在着色器。
- **不要把运动模糊写进每次纹理采样**（会让辉光和拖尾的每个采样点再乘 9）：运动模糊只对基础颜色做一次（9 次采样）。
- 辉光 8 采样 × 2 半径、拖尾 9 采样（间距加宽）足够；某效果强度为 0 时跳过整个循环。
- 优化前后：1920×1080 每帧约 2.0 秒 → 约 0.5 秒（4 倍），画质肉眼无差别。
- 估算：横屏 1080p、30fps、83 秒 ≈ 2500 帧，优化后终版约 20–25 分钟；先用 `--preview`（960×540、12fps）看节奏。
