# 炫技做法：着色器后期、一镜到底、画面事件对位旁白

这是一份做法说明，不是规则。想让画面更有质感、更连贯时可以参考；全部能力见 `capabilities.md`，用哪些由你判断。

## 1. 两层结构：Canvas 画内容，着色器统一加质感

模板默认每镜是 DOM 元素。要更强的质感时改用下面的结构（拷贝 `assets/fx/` 到项目根，在 `index.html` 里按 `avs-runtime.js` → `fx.js` → `lib.js` → `scenes.js` 的顺序引入）：

- `lib.js`：一块共享的 2D 画布 `L.C`。提供 `plate`（摄影图 + 推拉摇移）、`glow`、`text`（带辉光/描边/抖动）、`line`、`rect`、`dim`、`particles`（固定种子的粒子，纯时间函数）。
- `fx.js`：一道全屏 WebGL2 着色器，把 `L.C` 当纹理，统一加**色差、多采样辉光、横向拖尾（变形镜头光斑）、光扫转场、故障切片、屏幕震动、暗角、胶片颗粒、冷→暖调色**。参数由 `FX.apply(L.C, t, {warm, ca, bloom, sweep, glitch, shake, vig, flash, sat, streak})` 每帧传入。
- 每镜只做两件事：往 `L.C` 上画；写 `FXS.*` 参数。最后一次性 `FX.apply`。冲击（砍价、盖章、压下）= 同一时刻给 `shake / flash / ca / glitch` 一个指数衰减包络。
- 速度：无头 Chromium 用软件渲染（SwiftShader），1080×1920 约 0.1–0.4 秒/帧；90 秒、30fps 的片子终版约 15–25 分钟。**先用 `--preview`（540×960、12fps）看节奏。**

## 2. 把画面事件钉在旁白说出关键词的瞬间

比起凭感觉写"第 3.4 秒数字落下"，更准的做法是：

1. `voice.py` 生成每镜旁白后，`python scripts/transcribe.py <audio/vo/sXX.wav> --words` 得到每个字的开始时间。
2. 在 `scenes.js` 顶部建一张 `CUE` 表：`sXX: { 事件名: 镜内 lead + 词开始时间 }`。
3. 画面里的所有事件（数字落定、盖章、划线、点亮）都用 `CUE.sXX.事件名` 作起点。
4. 改旁白后重新转写、改 `CUE`，画面自动跟着。出片前用词级时间戳对一遍：偏差 > 0.45 秒的要修。

## 3. 每镜独立音色（冷 / 暖对比）

`project.json` 的镜头可写 `"voiceCfg": {"rate": "-6%", "pitch": "-6Hz"}` 覆盖全局音色参数。常用：问题段用"冷"（慢、低），转折后用"暖"（正常、略高），高潮段用"热"（快、略高）。叙事上需要对比时再用，每镜都换反而会削弱对比。

## 4. 竖屏短视频的节奏检查

- 竖屏短视频常见的做法是每 1.5–2.5 秒有一次画面事件。可以用运动量分析（相邻帧平均差）找出静止窗口，再加慢速推拉、呼吸光、漂浮粒子。
- 第一帧通常会被平台当封面，有完整内容更好；前 2 秒放一个让人停手的东西（反常识问句 + 强动作）是常见做法。
- 重要内容放在底部 190 像素以上、右侧 120 像素以内（平台按钮会盖住）。
- 数字：滚动 + 辉光 + 落定那一帧给 `flash/shake`，比静态字强得多。

## 5. 已知限制

- 着色器在软件渲染下较慢，每像素的大循环会明显拖慢渲染（当前辉光 8 采样、拖尾 9 采样）。
- 3D（Three.js）**不慢**：实测 1080p、80 个物理材质物体 + 软阴影 + 着色器后期，每帧约 0.25 秒，且逐字节确定（同一时间两次渲染像素一致）。见下一节。
- 生成式摄影图里偶有多余的字或手指问题：文字由代码排更稳，出图后看一遍再用。

## 6. 避免做成"带特效的 PPT"（2026-11 一次返工的体会）

- 每镜换一张整屏底图 + 叠字 + 光效，观感容易像 PPT。把生成图抠成透明底（`rembg`）作为实物浮在动画里，是我们试过更像视频的做法。
- **一镜到底**：一个世界 + 一条相机路径（单调三次样条，无过冲），场景只是时间段。相机的位置、缩放、速度驱动运动模糊；镜头间用"相机穿过去"代替淡入淡出。
- 主体是看得懂、有因果的具体物体（价格牌被砍、柱子被压平、灯被点亮、卡车开过、缆绳被压断 vs 一张网托住）时观众更容易跟上；抽象光点矩阵（一万个点）我们试过，观感像屏保，意义不明。数字可以靠 HUD 叠层，但要从一个世界里的事件"长出来"。
- 想让文字锐利，可以把文字画在着色器之后的叠层画布上（`L.useCtx(overlayCtx)`），避开辉光、色差和运动模糊；想要融入画面的辉光，就画在之前。
- 对比演示（一根线 vs 一张网）用屏幕空间的舞台、压暗背景、关掉拖尾和运动模糊，线条才读得清。

## 7. 软件渲染的性能预算（实测）

无头 Chromium 的 WebGL 走 CPU（SwiftShader），着色器采样数就是渲染时间：
- 每帧 JS 绘制约 30–60 ms，主要成本在着色器。
- 运动模糊如果写进每次纹理采样，会让辉光和拖尾的每个采样点再乘 9；只对基础颜色做一次（9 次采样）快得多。
- 辉光 8 采样 × 2 半径、拖尾 9 采样（间距加宽）足够；某效果强度为 0 时跳过整个循环。
- 优化前后：1920×1080 每帧约 2.0 秒 → 约 0.5 秒（4 倍），画质肉眼无差别。
- 估算：横屏 1080p、30fps、83 秒 ≈ 2500 帧，优化后终版约 20–25 分钟；先用 `--preview`（960×540、12fps）看节奏。

## 8. 要写实质感时用 Three.js 图层（已实测）

文章《Claude Opus 5.5 做视频进阶篇》的结论：接近专业三维动画的样片都是 Three.js 做的。我们同样支持，而且**和 2D 图层共用同一道后期着色器**（辉光、运动模糊、冷暖分界线、字幕叠层都继续有效）。

**什么时候用 3D，什么时候用 2D**

| 画面 | 选 | 原因 |
|---|---|---|
| 实物的体积、投影、材质（商品堆叠、杯子、货车、工厂、吊灯） | **Three.js** | 真实的光影、接触阴影、景深，2D 剪影做不出 |
| 镜头在空间里穿行、环绕、推拉 | **Three.js** | 真透视，不是靠缩放假装 |
| 价格牌、柱状图、考核表、划线、盖章、数字 | **Canvas 2D** | 文字和图形要锐利，3D 反而糊 |
| 光点、粒子、辉光、故障、冷暖调色 | **着色器后期** | 屏幕空间效果 |

**接入（四步）**
1. 把 `assets/fx/` 里的 `fx.js`、`lib.js`、`world.js`、`three-layer.js` 和 `vendor/three.module.min.js` 拷进项目；`assets/fx/examples/three-demo-index.html` 是页面模板（模块脚本放在 `scenes.js` 之前）。
2. `T3 = makeLayer(THREE, {w, h})` 建好渲染器、场景和相机；`T3.build(fn)` 在加载时一次性摆好物体（用 `rand(seed)` 而不是 `Math.random`，结果才可复现）。
3. 每帧 `T3.frame(t, fn)` 里只根据 `t` 设置相机和物体变换，然后 `T3.blit(L.X)` 把 3D 画到共享的 2D 画布上。
4. 其余照旧：2D 内容、`FX.apply`、字幕叠层。

**注意**
- 3D 适合画"物"；文字放在着色器之后的叠层更锐利（见第 6 节）。
- 三角面在 10 万以内、阴影贴图 1024 时，实测够快；雾可以做出景深感。
- 确定性：物体运动写成 `t` 的函数（不依赖物理引擎的实时积分和 `clock.getDelta()`），同一时间就能得到同一画面。
- Three.js 随包分发（`vendor/three.module.min.js`，r160，MIT，`LICENSE-three.txt`）；不需要联网。
- 有现成回归测试：`tests/test_pipeline.py::ThreeLayerTest`（无报错、同一 t 像素一致）。
